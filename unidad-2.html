Unidad 2

Sistemas LTI y convolución

Si un sistema es lineal e invariante en el tiempo, su respuesta al impulso lo describe por completo. Esta unidad convierte esa afirmación en un procedimiento de cálculo —la convolución— y en un lenguaje gráfico: los diagramas de bloques.

2.1Respuesta al impulso

La unidad 1 mostró que toda señal discreta puede escribirse como una suma de impulsos desplazados y ponderados. Si el sistema es lineal, la respuesta a esa suma es la suma de las respuestas; si además es invariante en el tiempo, la respuesta a δ[n − k] es h[n − k]. Encadenando ambas ideas aparece la convolución.

\[ x[n] = \sum_{k} x[k]\,\delta[n-k] \quad\xrightarrow{\;T\{\cdot\}\;}\quad y[n] = \sum_{k} x[k]\,h[n-k] \] El primer paso usa la propiedad de muestreo; el segundo, linealidad e invarianza. Sin alguna de las dos, la fórmula no vale.

Respuesta al impulso

h[n] = T{δ[n]} es la salida del sistema cuando la entrada es un impulso unitario. Para un sistema LTI, h caracteriza completamente al sistema: no hace falta conocer su estructura interna. En tiempo continuo, h(t) = T{δ(t)}.

2.2Suma de convolución

\[ y[n] = x[n] \ast h[n] = \sum_{k=-\infty}^{\infty} x[k]\,h[n-k] \] La variable de suma es k; n queda fijo en cada evaluación y se recorre después.

Convolución gráfica, paso a paso

  1. Cambiar de variable: dibujar x[k] y h[k] en función de k.
  2. Reflejar: obtener h[−k] espejando respecto al eje vertical.
  3. Desplazar: correr la señal reflejada n muestras para formar h[n − k].
  4. Multiplicar y sumar: sumar los productos x[k]·h[n − k] en la zona de solapamiento. Ese número es y[n].
  5. Repetir para cada n hasta que deje de existir solapamiento.

Tres verificaciones rápidas que ahorran errores:

  • Si x tiene Lx muestras y h tiene Lh, entonces y tiene Lx + Lh − 1 muestras.
  • El índice inicial de y es la suma de los índices iniciales de x y de h; el final, la suma de los finales.
  • La suma de todos los valores de y es el producto de las sumas de x y de h.

Ejemplo resuelto 2.1 — convolución con señales que empiezan antes de n = 0

x[n] = −2δ[n+2] − δ[n+1] + δ[n], h[n] = δ[n+1] + δ[n] − 2δ[n−1] (taller 4, punto 2).

  1. Escribir las secuencias con su índice inicial. x = {−2, −1, 1} desde n = −2; h = {1, 1, −2} desde n = −1.
  2. Longitud e índices del resultado. 3 + 3 − 1 = 5 muestras, desde n = −2 + (−1) = −3 hasta n = 0 + 1 = 1.
  3. Calcular cada muestra como suma de productos cruzados:
    \[ \begin{aligned} y[-3] &= (-2)(1) = -2 \\ y[-2] &= (-2)(1) + (-1)(1) = -3 \\ y[-1] &= (-2)(-2) + (-1)(1) + (1)(1) = 4 \\ y[\,0\,] &= (-1)(-2) + (1)(1) = 3 \\ y[\,1\,] &= (1)(-2) = -2 \end{aligned} \]
  4. Verificar. Σx = −2, Σh = 0, luego Σy debe ser 0: −2 − 3 + 4 + 3 − 2 = 0. ✔

y[n] = {−2, −3, 4, 3, −2} para n = −3 … 1

convolucion_discreta.m
%% Convolución discreta con manejo correcto de índices
x  = [-2 -1 1];   nx = -2:0;      % x[n] y su eje
h  = [ 1  1 -2];  nh = -1:1;      % h[n] y su eje

y  = conv(x, h);
ny = (nx(1)+nh(1)) : (nx(end)+nh(end));

stem(ny, y, 'filled'), grid on
xlabel('n'), ylabel('y[n]'), title('y[n] = x[n] * h[n]')

% Verificaciones que siempre deben cumplirse
assert(numel(y) == numel(x) + numel(h) - 1)
assert(abs(sum(y) - sum(x)*sum(h)) < 1e-9)
fprintf('y[n] = %s  (n = %d a %d)\n', mat2str(y), ny(1), ny(end))
convolucion_animada.m
%% Animación del proceso gráfico: reflejar, desplazar, multiplicar, sumar
x = [1 2 3 1];  nx = 0:3;
h = [1 1 -1];   nh = 0:2;
ny = (nx(1)+nh(1)):(nx(end)+nh(end));
y  = conv(x, h);

k  = -4:8;
xk = interp1(nx, x, k, 'nearest', 0);

for n = ny
    hk = interp1(nh, h, n - k, 'nearest', 0);   % h[n-k]

    subplot(2,1,1)
    stem(k, xk, 'filled'), hold on
    stem(k + 0.15, hk, 'Marker', 's'), hold off
    grid on, xlabel('k'), legend('x[k]', sprintf('h[%d-k]', n))
    title(sprintf('Solapamiento para n = %d   ->   y[%d] = %g', n, n, sum(xk.*hk)))

    subplot(2,1,2)
    stem(ny(ny <= n), y(ny <= n), 'filled'), grid on
    xlim([ny(1) ny(end)]), xlabel('n'), ylabel('y[n]')

    pause(0.6)                                  % ritmo de la animación
end

2.3Integral de convolución

\[ y(t) = x(t) \ast h(t) = \int_{-\infty}^{\infty} x(\tau)\,h(t - \tau)\,d\tau \]

El procedimiento es el mismo, con una diferencia decisiva: el solapamiento cambia de forma en intervalos de t, y en cada intervalo los límites de integración son distintos. La disciplina consiste en identificar primero los puntos de quiebre —aquellos valores de t donde un borde de h(t − τ) cruza un borde de x(τ)— y resolver una integral por tramo.

Ejemplo resuelto 2.2 — pulso contra exponencial

x(t) = 1 para 0 ≤ t ≤ 2 (cero fuera) y h(t) = 2e−tu(t), como en el taller 5.

  1. Puntos de quiebre. El borde móvil de h(t − τ) está en τ = t. Los bordes de x están en τ = 0 y τ = 2, así que los tramos son t < 0, 0 ≤ t < 2 y t ≥ 2.
  2. Tramo t < 0. No hay solapamiento: y(t) = 0.
  3. Tramo 0 ≤ t < 2. Solapamiento parcial, de τ = 0 a τ = t:
    \[ y(t) = \int_{0}^{t} 1 \cdot 2e^{-(t-\tau)}\,d\tau = 2e^{-t}\Big[\,e^{\tau}\,\Big]_{0}^{t} = 2\big(1 - e^{-t}\big) \]
  4. Tramo t ≥ 2. Solapamiento total, de τ = 0 a τ = 2:
    \[ y(t) = \int_{0}^{2} 2e^{-(t-\tau)}\,d\tau = 2e^{-t}\big(e^{2} - 1\big) \]
  5. Verificación de continuidad. En t = 2 el primer tramo da 2(1 − e−2) y el segundo 2e−2(e² − 1) = 2(1 − e−2). Coinciden. ✔

y(t) = 0 para t < 0;  2(1 − e−t) para 0 ≤ t < 2;  2(e² − 1)e−t para t ≥ 2

Regla práctica. Conviene reflejar y desplazar la señal más sencilla: la convolución es conmutativa, así que elegir bien reduce a la mitad el trabajo algebraico. Con un pulso y una exponencial, se refleja el pulso.
convolucion_continua.m
%% Convolución continua: aproximación numérica y solución simbólica
dt = 1e-3;  t = -2:dt:10;
u  = @(t) double(t >= 0);

x = u(t) - u(t-2);            % pulso de 0 a 2
h = 2*exp(-t).*u(t);          % exponencial causal

% La convolución discreta por dt aproxima la integral
y  = conv(x, h)*dt;
ty = (2*t(1)) : dt : (2*t(end));
ty = ty(1:numel(y));

plot(ty, y, 'LineWidth', 1.6), grid on, xlim([-2 10])
xlabel('t [s]'), ylabel('y(t)'), title('y(t) = x(t) * h(t)')

%% Comprobación simbólica tramo por tramo
syms tau T
y1 = int(2*exp(-(T-tau)), tau, 0, T)      % 0 <= T < 2 -> 2 - 2*exp(-T)
y2 = int(2*exp(-(T-tau)), tau, 0, 2)      % T >= 2      -> 2*exp(-T)*(exp(2)-1)

2.4Propiedades e interconexión de sistemas

Propiedades de la convolución y su lectura como interconexión
PropiedadExpresiónLectura en el sistema
Conmutativa\( x \ast h = h \ast x \)Da igual cuál señal se refleja.
Asociativa\( (x \ast h_{1}) \ast h_{2} = x \ast (h_{1} \ast h_{2}) \)Cascada: heq = h₁ ∗ h₂
Distributiva\( x \ast (h_{1} + h_{2}) = x \ast h_{1} + x \ast h_{2} \)Paralelo: heq = h₁ + h₂
Elemento neutro\( x \ast \delta = x \)El sistema identidad.
Desplazamiento\( x(t) \ast \delta (t - t_{0}) = x(t - t_{0}) \)Línea de retardo.
Derivación\( (x \ast h)' = x' \ast h = x \ast h' \)Basta derivar una de las dos señales.
Ancho del soporte\( T_\{y\} = T_\{x\} + T_\{h\} \)La convolución ensancha la señal.

La asociatividad y la distributividad son exactamente las reglas de serie y paralelo que reaparecerán en los diagramas de bloques, y en las unidades 3 y 4 se volverán simples productos y sumas de funciones de transferencia.

2.5Causalidad y estabilidad desde h

Para un sistema LTI, dos propiedades de la unidad 1 se leen directamente en la respuesta al impulso:

\[ \begin{aligned} \text{Causal:}\quad & h[n] = 0 \ \text{ para } n < 0 &\qquad & h(t) = 0 \ \text{ para } t < 0 \\ \text{Estable (BIBO):}\quad & \sum_{n} |h[n]| < \infty &\qquad & \int_{-\infty}^{\infty} |h(t)|\,dt < \infty \end{aligned} \] La condición de estabilidad es la sumabilidad o integrabilidad absoluta de h, no que h sea acotada.

Ejemplo resuelto 2.3 — tres respuestas al impulso

  1. h₁[n] = (0.8)ⁿu[n]. Σ|h₁| = 1/(1 − 0.8) = 5 < ∞. Causal y estable.
  2. h₂[n] = u[n]. Σ|h₂| = ∞ aunque h₂ está acotada por 1. Causal pero inestable: el acumulador ante un escalón crece sin límite.
  3. h₃(t) = e−2tu(t). ∫₀∞e−2tdt = 1/2 < ∞. Causal y estable.

Estar acotada no basta: lo que decide es que el área bajo |h| sea finita.

2.6Respuesta al escalón

La respuesta al escalón s(t) es la salida ante u(t) y guarda con h una relación directa que se usa constantemente en el laboratorio: generar un escalón es fácil, generar un impulso no.

\[ \begin{aligned} s(t) &= \int_{-\infty}^{t} h(\tau)\,d\tau &\Longleftrightarrow&\qquad h(t) &= \frac{d\,s(t)}{dt} \\ s[n] &= \sum_{k \le n} h[k] &\Longleftrightarrow&\qquad h[n] &= s[n] - s[n-1] \end{aligned} \] En la práctica se excita el circuito con un escalón y la respuesta al impulso se obtiene derivando la medida.

2.7Diagramas de bloques y su reducción

Un diagrama de bloques representa el mismo sistema con tres elementos: bloques (ganancias o funciones de transferencia), puntos de suma y puntos de bifurcación. Reducirlo consiste en aplicar reglas hasta dejar un único bloque entre la entrada y la salida.

Reglas de reducción de diagramas de bloques
ConfiguraciónBloque equivalente
Serie (cascada)\( G_{1} G_{2} \)
Paralelo\( G_{1} \pm G_{2} \)
Realimentación negativa\( G / (1 + G H) \)
Realimentación positiva\( G / (1 - G H) \)
Realimentación unitaria\( G / (1 + G) \)
Mover un sumador tras un bloqueMultiplicar la rama que entra por G
Mover un sumador antes de un bloqueDividir la rama que entra entre G
Mover una bifurcación tras un bloqueDividir la rama derivada entre G
Mover una bifurcación antes de un bloqueMultiplicar la rama derivada por G

Las tres configuraciones básicas

La configuración canónica de realimentación resume la estrategia de análisis que se usará en las unidades 3 y 4:

\[ \frac{Y(s)}{X(s)} = \frac{G(s)}{1 + G(s)\,H(s)} \] El denominador 1 + G(s)H(s) igualado a cero es la ecuación característica: sus raíces son los polos del sistema realimentado y deciden su estabilidad.

Ejemplo resuelto 2.4 — reducción en tres pasos

G₁ = 4/(s+2) en cascada con G₂ = 1/s, realimentados negativamente por H = 0.5, y con un bloque G₃ = 2 en paralelo.

  1. Cascada: G = G₁G₂ = 4 / [s(s + 2)].
  2. Lazo cerrado: Glc = G/(1 + GH) = [4/(s² + 2s)] / [1 + 2/(s² + 2s)] = 4 / (s² + 2s + 2).
  3. Paralelo: Geq = Glc + 2 = (2s² + 4s + 8) / (s² + 2s + 2).

Ecuación característica: s² + 2s + 2 = 0 → polos en s = −1 ± j. Parte real negativa: el lazo cerrado es estable.

reduccion_bloques.m
%% Reducción de diagramas de bloques con la Control System Toolbox
s  = tf('s');
G1 = 4/(s + 2);
G2 = 1/s;
H  = 0.5;
G3 = 2;

G   = series(G1, G2);          % cascada     (equivale a G1*G2)
Glc = feedback(G, H);          % lazo cerrado, realimentación negativa
Geq = parallel(Glc, G3);       % paralelo    (equivale a Glc + G3)

Geq = minreal(Geq)             % cancela polos y ceros repetidos
pole(Geq)
step(Geq), grid on, title('Respuesta al escalón del sistema reducido')

2.8Laboratorio en MATLAB

El curso pide construir una interfaz gráfica —GUIDE o, en versiones recientes, App Designer— que realice la convolución gráfica paso a paso. El núcleo de cálculo cabe en pocas líneas; el valor está en animar el desplazamiento y mostrar el solapamiento.

actualizar_convolucion.m
%% Núcleo de cálculo para la interfaz de convolución
% Se invoca desde el callback del deslizador que controla n.
function actualizar_convolucion(app)

    x   = str2num(app.EntradaX.Value);     % vector x[n]
    h   = str2num(app.EntradaH.Value);     % vector h[n]
    n0x = app.InicioX.Value;               % índice de la primera muestra de x
    n0h = app.InicioH.Value;

    nx = n0x:(n0x + numel(x) - 1);
    nh = n0h:(n0h + numel(h) - 1);
    ny = (nx(1) + nh(1)):(nx(end) + nh(end));
    y  = conv(x, h);

    n  = round(app.Deslizador.Value);      % desplazamiento actual
    k  = (ny(1) - 2):(ny(end) + 2);
    xk = interp1(nx, x, k,     'nearest', 0);
    hk = interp1(nh, h, n - k, 'nearest', 0);

    stem(app.EjeSuperior, k, xk, 'filled'), hold(app.EjeSuperior, 'on')
    stem(app.EjeSuperior, k, hk, 'Marker', 's'), hold(app.EjeSuperior, 'off')
    legend(app.EjeSuperior, 'x[k]', sprintf('h[%d-k]', n))

    stem(app.EjeInferior, ny, y, 'filled')
    app.Etiqueta.Text = sprintf('y[%d] = %g', n, sum(xk.*hk));
end
Sobre GUIDE. MATLAB retiró GUIDE en las versiones recientes y ofrece migrar la interfaz a App Designer desde el propio entorno. La lógica de cálculo es idéntica; solo cambia cómo se accede a los componentes: handles.eje en GUIDE frente a app.Eje en App Designer.
